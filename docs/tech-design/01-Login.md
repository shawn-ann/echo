## 〇、功能概述

- **目标**：提供登录入口，验证身份后进入纠错主页；MVP 使用**内置固定账号**（用户名/密码硬编码于服务端），无注册界面
- **入口**：根路径 `/` 未登录重定向至登录页；未登录/会话过期访问任何业务页面重定向登录页
- **出口**：登录成功后进入纠错主页（`02-Correction.md`）
- **关键约束**（PRD §4.6）：会话有效期内刷新/重开浏览器保持登录态；仅主动退出或会话过期需重登；退出后清除登录态、业务数据保留

## 二、数据模型（本功能）

### 2.1 users

| 字段 | 类型 | 说明 |
|------|------|------|
| `id` | UUID PK | |
| `username` | varchar(64) UNIQUE | |
| `password_hash` | varchar(255) | bcrypt 哈希 |
| `created_at` | timestamptz | |

- **固定种子账号**：服务端启动时种子化内置账号（用户名/密码 bcrypt），无注册接口；后续版本多账号体系平滑迁移（PRD §4.9）

### 2.2 登录会话（服务端内存存储）

> **存储位置**：登录会话**不落数据库**，存于服务端内存（进程内会话存储），仅对 `users` 表做账号持久化。

| 字段 | 说明 |
|------|------|
| `token` | opaque token（`secrets.token_urlsafe(32)` 生成，作为内存存储的 key） |
| `user_id` | 关联 `users.id` |
| `expires_at` | 默认 30 天滑动过期（`SESSION_TTL_DAYS`） |
| `created_at` / `last_used_at` | 创建与最近使用时间 |

- **令牌方案**：`secrets.token_urlsafe(32)` 生成 opaque token，存于**服务端内存**（不落 DB、无需哈希）；**登出即从内存删除**实现即时撤销；30 天无活动滑动过期
- **内存存储约束**：MVP 为单进程单实例（Docker Compose 单 `api` 容器），内存会话可用；**服务重启后全部会话失效**（用户需重新登录，属 MVP 可接受取舍）；后期多实例/重启无感需引入共享会话存储（如 Redis），记为后续增强
- **滑动过期**：每次鉴权成功更新 `expires_at`（`SESSION_TTL_DAYS` 配置）

## 三、交互流程

### 3.1 登录时序

```
User        Frontend          Backend              DB
 │ 填写用户名/密码 │                │                   │
 │──提交──▶│ 前端非空校验          │                   │
 │        │ 失败→字段提示，不发请求│                   │
 │        │ 通过→按钮进入加载态    │                   │
 │        │──POST /api/v1/auth/login──▶│               │
 │        │                │ 校验固定账号            │
 │        │                │──查询 users──▶          │
 │        │                │◀──返回用户──            │
 │        │                │ bcrypt 校验密码         │
 │        │                │ 生成 token，写入内存会话 │
 │        │◀──200 {token, expires_at}──│               │
 │        │ localStorage 持久化 token               │
 │        │ 跳转纠错主页（AuthGuard 放行）            │
```

### 3.2 会话保持 / 退出

- 前端在 `localStorage` 持久化 token，API 客户端统一注入 `Authorization: Bearer <token>`
- 刷新/重开浏览器：`AuthGuard` 读 token → 调 `GET /auth/me` 校验 → 有效放行 / 失效重定向登录页
- **退出**：调 `POST /auth/logout`（服务端从内存会话删除）→ 前端清 token → 回登录页；业务数据保留（存 DB）
- **401 拦截（会话过期）**：业务请求返回 401 时，**保留当前页面不跳转**，弹出提示「会话已过期，请重新登录」+ 「重新登录」入口；用户消息/输入内容不丢失，重新登录后会话上下文仍在

## 四、接口契约

### 4.1 POST /api/v1/auth/login

请求：
```json
{ "username": "demo", "password": "demo1234" }
```
响应 200：
```json
{ "token": "<opaque-token>", "expires_at": "2026-09-07T12:00:00Z", "user": { "id": "...", "username": "demo" } }
```
错误：`400`（参数缺失，`code: VALIDATION_ERROR`）、`401`（`code: AUTH_INVALID_CREDENTIALS`，「用户名或密码错误」）

### 4.2 POST /api/v1/auth/logout（需鉴权）

- 请求：`Authorization: Bearer <token>`
- 行为：从服务端内存会话删除对应 token
- 响应 204；token 已失效时返回 401（幂等处理，前端仍清本地 token）

### 4.3 GET /api/v1/auth/me（需鉴权）

- 请求：`Authorization: Bearer <token>`
- 响应 200：`{ "id": "...", "username": "demo" }`
- 令牌有效校验 + 滑动续期；失败返回 401（`code: AUTH_TOKEN_EXPIRED` / `AUTH_UNAUTHORIZED`）

## 五、三态与错误处理

| 状态 | 呈现 | 说明 |
|------|------|------|
| 加载态 | 登录按钮禁用 + 指示器 | 防止重复提交 |
| 空态 | 不适用（表单页无列表空态） | — |
| 错误态 | 表单区错误提示，输入内容保留 | 字段级校验 / 服务端错误 |

| 场景 | 反馈 | 保留内容 |
|------|------|----------|
| 用户名为空提交 | 「请输入用户名」（前端校验，不发请求） | 密码保留 |
| 密码为空提交 | 「请输入密码」 | 用户名保留 |
| 用户名或密码错误 | 「用户名或密码错误」（401） | 用户名保留、密码清空 |
| 网络/服务异常 | 「登录失败，请稍后重试」（5xx/超时） | 全部保留 |

| 场景 | 前置 | 触发 | 预期 | 关联 |

| 会话保持（重开） | 已登录 | 关闭重开浏览器 | 保持登录态（会话有效期内） | AC-L-04 |
| 未登录访问业务页 | 未登录 | 访问纠错主页 | 重定向登录页 | AC-L-05 |
