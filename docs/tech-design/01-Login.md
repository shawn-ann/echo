**所属**：地道英语纠错 · 智能笔记本 | **版本**：V0.6 | **状态**：草稿 | **日期**：2026年8月
**对应 PRD**：`PRD/pages/01-Login.md`、`PRD/Overview.md` §3.1

> 本文档为登录功能的**详细技术设计**（页面组件、数据模型、交互流程、接口契约、场景矩阵）。顶层约定不重复定义，统一引用 `00-Architecture.md`。

## 〇、功能概述

- **目标**：提供登录入口，验证身份后进入纠错主页；MVP 使用**内置固定账号**（用户名/密码硬编码于服务端），无注册界面
- **入口**：根路径 `/` 未登录重定向至登录页；未登录/会话过期访问任何业务页面重定向登录页
- **出口**：登录成功后进入纠错主页（`02-Correction.md`）
- **关键约束**（PRD §4.6）：会话有效期内刷新/重开浏览器保持登录态；仅主动退出或会话过期需重登；退出后清除登录态、业务数据保留

### 0.1 空白纠错页（登录后落地页占位）

> **目的**：登录流程实现时，需提供一个**空白的纠错主页占位页**作为登录成功后的落地页，用于**完整验证「登录 → 落地 → 退出」流程**（含导航栏展示登录用户名）。纠错功能正式实现后，此占位页由 `02-Correction.md` 的完整纠错主页替换。

**占位页要求**：

| 项 | 要求 |
|----|------|
| 内容 | 仅展示**导航栏（Logo + 产品名 + 当前登录用户名 + 「退出」按钮）** + 空白内容区 |
| 鉴权 | 未登录访问 → 重定向登录页（AuthGuard） |
| 退出 | 点击「退出」→ 调 `POST /auth/logout` → 清 token → 回登录页 |
| 关联 | 验证项见 §7.2 U-L-01 / U-L-05 / U-L-09，及 §7.3 验证顺序 |

> 该占位页由登录功能交付，不依赖纠错功能开发进度；`02-Correction.md` 正式实现时替换占位内容。

## 二、数据模型（本功能）

### 2.1 users

| 字段 | 类型 | 说明 |
|------|------|------|
| `id` | UUID PK | |
| `username` | varchar(64) UNIQUE | 用户名 |
| `password_hash` | varchar(255) | bcrypt 哈希 |
| `status` | enum | 账号状态：`active`（正常）/ `disabled`（禁用）/ `deleted`（删除） |
| `created_at` | timestamptz | |

- **固定种子账号**：服务端启动时种子化内置账号（用户名/密码 bcrypt），无注册接口；后续版本多账号体系平滑迁移（PRD §4.9）
- **状态语义**：`disabled` 账号禁止登录（提示账号不可用）；`deleted` 账号视为不存在（校验按未找到处理）；MVP 无管理界面，状态变更经服务端数据维护，为后期管理能力预留

### 2.2 登录会话（DB 持久化）

> **存储位置**：登录会话**持久化于数据库**（`sessions` 表），多 worker/服务重启下登录态不丢失。

| 字段 | 类型 | 说明 |
|------|------|------|
| `id` | UUID PK | |
| `user_id` | UUID FK → users.id | |
| `token_hash` | varchar(255) | opaque token 的 SHA-256 哈希（不存明文） |
| `expires_at` | timestamptz | 默认 30 天滑动过期（`SESSION_TTL_DAYS`） |
| `created_at` / `last_used_at` | timestamptz | |

- **令牌方案**：`secrets.token_urlsafe(32)` 生成 opaque token，DB 存哈希；**登出即删除该行**实现即时撤销；30 天无活动滑动过期
- **滑动过期**：每次鉴权成功更新 `expires_at`（`SESSION_TTL_DAYS` 配置）
- **多 worker 支持**：会话落库，多进程/多实例下共享登录态，无内存会话的一致性限制

## 三、交互流程

### 3.1 登录时序

```
User        Frontend          Backend              DB
 │ 填写用户名/密码 │                │                   │
 │──提交──▶│ 前端非空校验          │                   │
 │        │ 失败→字段提示，不发请求│                   │
 │        │ 通过→按钮进入加载态    │                   │
 │        │──POST /api/v1/auth/login──▶│               │
 │        │                │ 校验固定账号            │
 │        │                │ 检查 status（禁用/删除则拒绝）│
 │        │                │──查询 users──▶          │
 │        │                │◀──返回用户──            │
 │        │                │ bcrypt 校验密码         │
 │        │                │ 生成 token，写入 sessions 表│
 │        │◀──200 {token, expires_at}──│               │
 │        │ localStorage 持久化 token               │
 │        │ 跳转纠错主页（AuthGuard 放行）            │
```

### 3.2 会话保持 / 退出

- 前端在 `localStorage` 持久化 token，API 客户端统一注入 `Authorization: Bearer <token>`
- **取舍说明（localStorage）**：token 存 localStorage 存在 XSS 窃取风险（可被脚本读取）；MVP 固定账号 + 自用场景接受此取舍，后期账号体系完善时迁移至 HttpOnly Cookie
- 刷新/重开浏览器：`AuthGuard` 读 token → 调 `GET /auth/me` 校验 → 有效放行 / 失效重定向登录页
- **退出**：调 `POST /auth/logout`（服务端删除 `sessions` 表对应 token 行）→ 前端清 token → 回登录页；业务数据保留（存 DB）
- **401 拦截（会话过期）**：业务请求返回 401 时，**保留当前页面不跳转**，弹出提示「会话已过期，请重新登录」+ 「重新登录」入口；用户消息/输入内容不丢失，重新登录后会话上下文仍在

## 四、接口契约

> **MVP 取舍**：不提供登录失败限速、账号锁定等暴力破解防护（固定账号 + 自用场景，属已知取舍）；后期账号体系完善时补充防护机制。

### 4.1 POST /api/v1/auth/login

请求：
```json
{ "username": "demo", "password": "anshuai1234567" }
```
响应 200：
```json
{ "token": "<opaque-token>", "expires_at": "2026-09-07T12:00:00Z", "user": { "id": "...", "username": "demo" } }
```
错误：`400`（参数缺失，`code: VALIDATION_ERROR`）、`401`（`code: AUTH_INVALID_CREDENTIALS`，「用户名或密码错误」；**deleted 账号同样返回此错误**，不泄露账号状态）、`403`（`code: AUTH_ACCOUNT_DISABLED`，「账号不可用」，disabled 账号）

### 4.2 POST /api/v1/auth/logout（需鉴权）

- 请求：`Authorization: Bearer <token>`
- 行为：删除 `sessions` 表中对应 token 行
- 响应 204；token 已失效时返回 401（幂等处理，前端仍清本地 token）

### 4.3 GET /api/v1/auth/me（需鉴权）

- 请求：`Authorization: Bearer <token>`
- 响应 200：`{ "id": "...", "username": "demo" }`
- 令牌有效校验 + 滑动续期；失败返回 401（`code: AUTH_TOKEN_EXPIRED` / `AUTH_UNAUTHORIZED`）

## 五、三态与错误处理

| 状态 | 呈现 | 说明 |
|------|------|------|
| 加载态 | 登录按钮禁用 + 指示器 | 防止重复提交 |
| 空态 | 不适用（表单页无列表空态） | — |
| 错误态 | 表单区错误提示，输入内容保留 | 字段级校验 / 服务端错误 |

| 场景 | 反馈 | 保留内容 |
|------|------|----------|
| 用户名为空提交 | 「请输入用户名」（前端校验，不发请求） | 密码保留 |
| 密码为空提交 | 「请输入密码」 | 用户名保留 |
| 用户名或密码错误 | 「用户名或密码错误」（401） | 用户名保留、密码清空 |
| 网络/服务异常 | 「登录失败，请稍后重试」（5xx/超时） | 全部保留 |
